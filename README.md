# 🎮 Multiplayer Game Socket Server
비동기 TCP 소켓 기반의 서버를 직접 구축하여, 실시간 멀티플레이 게임에서 발생하는  
다양한 이벤트를 처리하고 구조적으로 확장 가능한 형태로 설계했습니다.  
성능 병목, Lock 경합, 패킷 처리 자동화 등의 문제를 해결하며 **지속 가능한 구조**에 집중했습니다.


## 🛠️ 기술 스택
- Language: **C#**
- Network: **TCP Socket, Protocol Buffer**
- Backend: **ASP.NET Core, EF Core**
- Database: **MS-SQL**
- Tools: **Visual Studio, Git**
- Client: **Unity**


## 📐 주요 기능
| 기능            | 설명 |
|-----------------|------|
| TCP 소켓 서버      | 비동기 방식으로 클라이언트 수천 개 동시 접속 가능 |
| 패킷 직렬화 구조    | Protocol Buffer 사용으로 효율적인 메시지 송수신 |
| PacketGenerator | .proto 파일 기반 클라/서버 핸들러 자동 생성 도구 |
| JobQueue 처리    | Lock 제거, 스레드 병목 최소화를 위한 순차 처리 구조 |
| 컨텐츠 구현       | 인벤토리, 채팅, 상점, 우편함, 퀘스트 등 주요 시스템 구축 |


## ✔ 문제 해결 사례

###  인벤토리 반영 지연 → JobQueue로 구조 개선

- **문제**: 아이템 습득 + 다수 이벤트 동시 발생 시 인벤토리 지연/누락 현상
- **해결**: 유저 단위 JobQueue로 작업 순서 보장 → Lock 제거
- **결과**: 병목 해소 및 정합성 유지, 안정적인 아이템 처리 구조 확보


###  패킷 등록 자동화 → PacketGenerator 도구 제작

- **문제**: .proto 수정 시 클라/서버 양쪽 코드 반복 작성 → 오타/누락 위험
- **해결**: .proto → Client/Server PacketManager 코드 자동 생성 도구 작성
- **결과**: 개발 생산성 향상 + 일관성 유지 + 유지보수 용이


###  우편 시스템 구조 설계 → 서버 검증 기반 안정화

- **문제**: 비동기 도착 / 수정 방지 / 상태 동기화 등 복잡한 로직 요구
- **해결**: 서버 중심 DB 검증 구조 설계 → 클라이언트는 UI만 반영
- **결과**: 메세지 정합성 확보 + UX 일관성 유지 + 보안 강화
